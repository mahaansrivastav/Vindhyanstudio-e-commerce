DNS, explained

A short, practical guide to how a domain name reaches a website, using the real setup of vindhyanstudio.in as the example.

1. What DNS does 2. Who's who: registrar, DNS host, web host 3. What happens when you type a URL 4. Record types you'll actually use 5. TTL and "propagation" 6. Our real configuration 7. How HTTPS certificates fit in 8. Checking DNS yourself 9. Common mistakes 10. Quick self-check

1What DNS does

Computers find each other by IP address (like 75.2.60.5). People remember names (like vindhyanstudio.in). The Domain Name System (DNS) is the internet's phone book: it turns names into addresses.

One sentence to remember: DNS doesn't host your website. It only tells browsers where your website is.

2Who's who

Three separate roles. Sometimes one company does several, but thinking of them separately avoids most confusion.

Registrar
Where you bought the name and renew it yearly. For us: GoDaddy.
DNS host
Where the records live (the phone-book entries). For us: also GoDaddy (nameservers ns45/ns46.domaincontrol.com).
Web host
Where the website runs. Frontend: Netlify. Backend API: Render.

The NS (nameserver) records decide which company is the DNS host. You could move the DNS host to Netlify by changing nameservers at GoDaddy. We chose to keep DNS at GoDaddy and only point two records at Netlify.

3What happens when you type a URL

1
Browser asks a resolverUsually your ISP's or Google's (8.8.8.8). If it already knows the answer (cached), it replies instantly.
2
Resolver walks the treeRoot servers say "ask the .in servers"; the .in servers say "ask GoDaddy's nameservers (ns45/ns46.domaincontrol.com)".
3
GoDaddy answers"vindhyanstudio.in has an A record: 75.2.60.5". The resolver caches this for the TTL.
4
Browser connectsIt opens HTTPS to 75.2.60.5 (Netlify) and says "I want vindhyanstudio.in". Netlify serves your site.

Name column cheat sheet

@ = the domain itself (vindhyanstudio.in). www = www.vindhyanstudio.in. api = api.vindhyanstudio.in.

Why A for the root but CNAME for www? The DNS standard doesn't allow a CNAME at the root (@), because the root also needs NS and SOA records. So the root uses an A record with the host's IP, and subdomains use a CNAME to the host's name. A CNAME is nicer because if Netlify changes its IPs, the name still works.

5TTL and "propagation"

TTL (time to live) is how long resolvers may cache an answer, e.g. 600 seconds = 10 minutes, 3600 = 1 hour.

"Propagation" isn't data travelling. It's old cached answers expiring around the world. After you change a record, some people see the new value immediately and others only after their cached copy's TTL runs out.

Tip: Before a planned change (e.g. moving the backend), lower the TTL to 300 a day earlier. The switch then takes effect within about 5 minutes.

7How HTTPS certificates fit in

A certificate proves to the browser that the server really is vindhyanstudio.in (the padlock icon). Netlify gets one free from Let's Encrypt:

1
DNS must point to Netlify firstThat's what "Waiting on DNS propagation" means.
2
Let's Encrypt checks controlIt fetches a test file from your domain, and that only works if DNS reaches Netlify.
3
Certificate issued and auto-renewedValid 90 days; Netlify renews it automatically. Nothing to buy.

Render does the same for api.vindhyanstudio.in once you add it as a custom domain there.

8Checking DNS yourself

In a terminal (macOS / Linux):

dig +short vindhyanstudio.in           # → 75.2.60.5
dig +short www.vindhyanstudio.in       # → vindhyan-studio.netlify.app. + IPs
dig +short NS vindhyanstudio.in        # → ns45/ns46.domaincontrol.com.
dig @8.8.8.8 +short vindhyanstudio.in  # ask Google's resolver directly
curl -I https://vindhyanstudio.in      # does the site answer over HTTPS?

On Windows: nslookup vindhyanstudio.in. Online: dnschecker.org shows what resolvers around the world currently see.

9Common mistakes

Two A records on @ (old "Parked" plus new)

Visitors randomly hit the parking page, and the certificate can fail. Keep exactly one: 75.2.60.5.

Domain forwarding left on at GoDaddy

Forwarding overrides your records. Turn it off when the domain points to a host.

Typing https:// or a trailing slash in a DNS value

DNS values are bare names or IPs: vindhyan-studio.netlify.app, not https://vindhyan-studio.netlify.app/.

Changing nameservers by accident

If NS records change, all other records at GoDaddy stop mattering, because a different company now answers. Only change NS deliberately.

Deleting email records (MX / TXT / DMARC)

Your website keeps working, but email delivery breaks or lands in spam. Only edit the records you mean to change.

Site loads but products don't (CORS error)

DNS is fine. The backend doesn't trust the new domain yet. Add it to APP_CORS_ORIGINS on Render.

Panicking during propagation

Mixed results for up to the TTL (sometimes a few hours) are normal. Check with dig @8.8.8.8 or dnschecker.org.

10Quick self-check

Where do I renew the domain every year?

At the registrar: GoDaddy.

I want shop.vindhyanstudio.in to show the same site. Which record?

A CNAME: name shop, value vindhyan-studio.netlify.app. Then add it as a domain alias in Netlify.

The backend moves from Render to another host. What changes?

With api.vindhyanstudio.in in use: update only that CNAME at GoDaddy (and the new host's custom domain). The frontend doesn't change.

Why can't I use a CNAME for @?

The root must also hold NS/SOA records, and a CNAME can't coexist with other records. So the root uses an A record.

I changed a record 5 minutes ago and still see the old site. Broken?

Probably not. Your resolver is still using the cached answer until its TTL expires.
